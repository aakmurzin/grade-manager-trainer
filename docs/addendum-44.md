## Методологическая заметка — confound, не только RNG

Регрессия `addendum-36` (`[5000, 7000]` хуже `[4500, 6500]`) была артефактом не только
невоспроизводимых seeds (`addendum-41`/`42`), но и **скрытого confound**:

- A36 тестировал `[5000, 7000]` **без** Accountant hire trigger
- A37 подтверждал `[4500, 6500]` **уже с** ним

Сравнивались не два чека при одинаковых условиях, а «чек + Accountant» против
«чек без Accountant». Принцип «один рычаг за раз» формально соблюдался внутри каждого
addendum, но два фикса оказались близко по времени и не были явно переразведены при
меж-addendum сравнении.

Урок зафиксирован в `docs/balance-spec.md` §14 (checklist: full config snapshot при каждом
сравнении).
