Два независимых рычага после A20: **spawn 0.75w** (экономика) и **периодический пересмотр headcount** (агент). Чек $600–700 не трогали.

## 1. Spawn 0.75w — не константа, а цикл в движке

`leadFrequencyWeeks` для Trainee Design: **1.0 → 0.75**. Одного числа мало: `tickWeek` делал `Math.max(1, interval)`, и 0.75w снова становился 1 лид/неделю.

Цикл теперь сливает таймер в `while`:

- интервал может быть дробным (`Math.max(0.25, …)`);
- часть недель даёт **2 лида** (~1.33/нед при 0.75);
- Product / IT / Marketing (1.8 / 2.5 / 4) не меняются.

Чек **$600–700** и force-assign **1w** без изменений.

Батч spawn-only (старый агент, без review): `playtest-results/batch-addendum-21-spawn.json`  
Повтор без review-найма: `batch-addendum-21-spawn-replicated.json` (банкротство снова 8.3%, mean −6.7k — не разовый удачный прогон).

| | A20 (чек, spawn 1.0) | A21 spawn 0.75 |
|---|---|---|
| Bankrupt | 3/12 (25%) | **1/12 (8.3%)** |
| 4Q без банкротства | 9/12 | **11/12** |
| **Cumulative NP > 0** | **0/12** | **0/12** |
| Q3 или Q4 в плюсе | 1/12 | **8/12** |
| Q4 в плюсе | 0/12 | **7/12** |
| Mean NP | −10.3k | **−7.9k** |
| Q2 median NP | −1.7k | **+$513** |
| Q4 median NP | −891 | **+$190** |
| Лучший полный cum | −6176 | **−2932** (s12) |
| assign_project / сессию | 26.7 | **39.9** |
| Designer hires median | 2 | 2 |
| Last hire week median | 6 | 6 |

Тот же штат (медиана 2 Designer, последний найм ~w6), **другой throughput**. Q4-удержание, которого не дал чек, появляется за счёт объёма. Оговорка A21 про «плотный spawn усилит очередь при заморозке» на этом батче **не сработала как провал spawn**: skip_project share 30.7% → 19.8%.

Ближе всего к cum+: spawn s12 Q=[−5432, **+2225**, **+578**, −303] cum **−2932**; s10 Q2–Q4 все плюс, cum −4348. Повтор без review: s09 cum **−802**, Q=[−4105, −674, **+3673**, **+304**].

## 2. Агент — пересмотр headcount, не заморозка и не перенайм

Диагноз A20-s05 (1S+2D с w6, promotion без роста штата) верен **на spawn 1.0w**. На 0.75w тот же `reasonable` уже нанимает 2 Designer + 2–3 Sales в Q1; потолок «кап 2» редко душит throughput.

Первая попытка «нанять 3-го, потому что все заняты» (Q2, at-capacity): `batch-addendum-21-overhire.json` — **банкротство 67%**, mean −10.3k. При 0.75w spawn + delivery 1w **двое Designer уже покрывают поток**; третья зарплата — overstaffing, симметричный A11 (там слишком рано, здесь слишком много).

Итоговая эвристика (тот же класс, что A11 — агент, не экономика):

| | Правило |
|---|---|
| Q1–Q2 | как A11: первый Designer по work signal; второй только если `queued > idle`; кап 2 |
| С Q3 (w≥25) | review каждые 4 недели / после K=4 недель загрузки |
| Extra hire | только **живая очередь** (`queued` projects ≥ 3 или leads ≥ 3), runway ≥ 35% start budget, cooldown 8w, max 3 Designer / 3 Sales |
| Не нанимать | если все заняты, а очередь пустая — это нормальная утилизация, не сигнал роста |

UI-hint и LLM prompt говорят то же: не путать загрузку с очередью.

Официальный combined: `playtest-results/batch-addendum-21-combined.json` (spawn 0.75 + эта эвристика). Review сработал **3 раза / 12 сессий**. Лучшие cum как раз **без** 3-го Designer (s03 −1139, s12 −1713).

| | Spawn-only | Combined (Q3, queue≥3) |
|---|---|---|
| Bankrupt | 8.3% | 41.7% (n=12 шумно; review почти не стрелял) |
| Mean NP | −7.9k | −7.9k |
| Best cum | −2932 | **−1139** (s03, Q2–Q4 все плюс) |
| Review hires | 0 | 3 |

Два рычага **не сложились** в cum-positive. Экономика spawn — основной выигрыш. Агрессивный рост штата вреден; консервативный review — страховка, не двигатель прибыли.

## 3. Что осталось до cum-positive

Форма fair/winnable уже есть: Q1 минус, Q2–Q4 часто плюс. Дыра — **глубина Q1** (медиана ≈ −$6–7k). Лучшие полные прогоны: −802 / −1139 / −1713 / −2932. Сдвиг Q1 на ~$2k дал бы пересечение нуля без нового spawn.

Не делать: ещё плотнее spawn при том же штате (риск очереди) и 3-й Designer «потому что заняты». Следующий рычаг — **Q1** (стартовый бюджет / ранняя воронка), чек и 0.75w держать.
